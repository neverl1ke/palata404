# Avatar Core 1.0 — ізольована лабораторія

Статус: **механічний прототип; художнє приймання не завершене**. Робота в `feature/avatar-core-1`, початкова точка `f70b7e5`. Основна гра не імпортує новий рушій; оригінальні PNG, Paper Doll, баланс і формат збережень не змінені.

## Запуск

З кореня цієї робочої гілки:

```sh
python -m http.server 8000
```

Відкрити `http://localhost:8000/avatar-lab/`. Звіт і знімки: `http://localhost:8000/review/avatar-core-1/`.

Для перегляду без сервера:

```sh
python tools/bundle-avatar-lab.py
python tools/build-avatar-core-gallery.py
```

`review/avatar-core-1/avatar-lab-offline.html` — самодостатній інтерактивний Lab: PNG та модулі вбудовані, мережа не потрібна. Звичайний `avatar-lab/index.html` потребує HTTP через правила браузера для модулів; автономний файл перевірений через `file://`. Згенеровані великі HTML не потрапляють до Git: їх можна відтворити або отримати в пакеті перегляду.

## Архітектура

- `avatar-core/engine.mjs`: один Canvas 2D рушій, керування станом, диханням, переходами, кешами, Hi-DPI, життєвим циклом і кріпленнями.
- `avatar-core/math.mjs`: матриці, FK, дволанкова IK до зап’ястя та незалежний поворот кисті. Кістки не масштабуються; недосяжна ціль явно позначається `clamped`.
- `avatar-core/weapon-controller.mjs`: окремий Weapon Attachment Controller. Спільні PNG для обох статей, первинна та опорна точки, масштаб, зміщення реєстрації й кут.
- `avatar-core/skin.mjs`: неперервні ваги шкіри біля плечей/ліктів/зап’ясть. Жорсткі ділянки кешуються як `Path2D` і малюються групами; деформуються тільки перехідні ділянки.
- `avatar-core/rigs/{male,female}_rig.json`: два незалежно виміряні риги. Спільне полотно 941×1672, власні pivots, parent, bounds, localPivot, bindOffset, пози й амплітуди.
- `avatar-core/assets/`: похідні сегменти оригінальних тіл, шкіра рук і прості тестові рукави. `tools/prepare-avatar-core.py` відтворює їх без перезаписування баз.
- `avatar-core/weapons.json`: три **схематичні тестові** предмети, не затверджений ігровий арт. `none` означає відсутність шару зброї.
- `avatar-lab/catalog-bridge.js`: використовує чинні каталог, палітру, маски та алгоритм crown clip. `script.js` і `wardrobe.js` тут не запускаються; функції запису сейву не викликаються.

`right` — анатомічна права рука, тобто ліва сторона зображення. Координати та pivots задані у вихідних пікселях. PNG сегментів обрізані для економії; `bounds` повертають їх у спільне полотно. `localPivot` — pivot відносно верхнього лівого кута цього PNG; він може лежати за межами cropped bitmap. `bindOffset` — відступ від pivot батька. У runtime використовуються світові матриці, еквівалентні цій ієрархії.

## Рендер і шари

Задні частини волосся → базова анатомія → чинні face/hair накладки → зброя → передні кисті та прив’язані до них предмети. Face/body masks застосовуються до вихідних координат до деформації. Crown clip береться з наявного `paper-doll.js`; нової таблиці посадок зачісок не створювали. Плечі залежать від матриці грудної клітки, голова й нижня частина тіла не рухаються.

При `idle` без дихання кеш збирається з дев’яти неперекривних сегментів на вихідному полотні. Це не підміна рига вихідним PNG: окремий тест відновлює всі видимі пікселі з сегментів та порівнює з джерелом. У рухомих станах — FK/IK та source-pixel skinning. Прикладні накладки, прив’язані з `skinned:true`, композитяться в кеш шкіри перед деформацією, щоб не малювати нову сітку для кожного рукава.

Схематична зброя розміщена над переднім волоссям і під кистями. Поле `order` у її даних описує цей передній прохід; довільне пересортування всього персонажа через це поле поки не є публічним API. Діагностичні межі показують вихідні PNG-сегменти під їхніми кістками; skinned краї можуть відрізнятися від цих прямокутників.

## API

```js
import { AvatarEngine } from './avatar-core/engine.mjs';
const avatar = await AvatarEngine.create(canvas, { gender: 'female' });
avatar.setPose('rifle'); // idle / melee / pistol / rifle
avatar.setWeapon('none'); // також melee / pistol / rifle
avatar.setOptions({
  breathing: true,
  cycleMs: 4000,
  amplitude: 1,
  weaponSwayPx: 2, // CSS px при поточному масштабі, не backing pixels Retina
  transitionMs: 320,
  pistolSupport: false
});
avatar.pause(false);
await avatar.setGender('male');
avatar.pause(true);
avatar.step(1000 / 60);
avatar.setLayerVisible('weapon', false);
avatar.destroy();
```

Класи можна одночасно створювати для різних canvas: стан поз/статі незалежний, кеш завантажених PNG спільний і обмежений 96 записами. Перемикання статі та зовнішності має захист від завершення застарілого асинхронного завантаження. На прихованій вкладці rAF зупиняється; прихований час не додається після повернення.

Пози калібровані окремо для кожної статі. Відповідно до останніх референсів: ніж опущений, пістолет біля правого плеча з опущеною лівою рукою, автомат діагонально перед тулубом. Варіант підтримки пістолета другою рукою з початкового ТЗ доступний окремим перемикачем. Прикладені користувачем зображення не додані до ресурсів.

```js
await avatar.bindEquipment({
  id: 'sleeve-r-upper',
  segment: 'rightUpper',
  sourceByGender: {
    male: '/assets/my-male-sleeve.png',
    female: '/assets/my-female-sleeve.png'
  },
  placementByGender: {
    male: { x: 240, y: 330, width: 100, height: 285 },
    female: { x: 270, y: 325, width: 85, height: 260 }
  },
  skinned: true,
  order: 1
});
avatar.unbindEquipment('sleeve-r-upper');
```

Наведені числа для рукава — **приклад контракту**, не затверджена посадка одягу. Тестові реальні накладки лабораторії беруть точні `bounds` із відповідного рига. Доступні сегменти: `head`, `torso`, `lower`, `rightUpper`, `rightFore`, `rightHand`, `leftUpper`, `leftFore`, `leftHand`. Для звичайного жорсткого кріплення `skinned` можна не задавати. Вибір джерела/розташування за статтю виконується після зміни рига; предмети з `genders` приховуються для іншої статі. Збій завантаження не залишає pending-предмет.

## Зовнішність і сейви

`setAppearance({layers, bodyMask, crown})` не виконує записів у localStorage. Bridge підключає чинні обличчя, палітру й front/rear волосся. У лабораторії є окремі стани «Оригінальний PNG» і «Базове обличчя як у грі»: останній для жінки використовує чинну стандартизовану native-накладку, перший показує незмінений сирий базовий PNG.

Кнопка читання сейву читає лише `palata404_paper_doll` поточного origin. Локальний файл не має доступу до сховища GitHub Pages. Оригінальні комплекти `patientLoadout` / `combatLoadout`, невідомі поля й прогрес не перезаписуються. Некоректні або несумісні ID нормалізуються **тільки для preview**. Нова міграція формату не потрібна й не виконується.

Старі суцільні PNG одягу з намальованими рукавами не стають анімованими автоматично. Вони залишаються у чинній грі; для Avatar Core потрібні зареєстровані сегменти одягу. На цьому етапі перевірено лише API та прості тестові рукави, не створено новий повноцінний гардероб.

## Межі готовності

Вихідні плоскі PNG не містять прихованих поверхонь суглобів, перспективно скорочених передпліч і стиснутих пальців. Незмінні довжини кісток не дають точно відтворити перспективу референсів. Skinning підтримує зв’язність, але на сильних згинах залишаються кутові фрагменти, різкі текстурні межі й самоперекриття сітки: це підтверджені незакриті дефекти прототипу. Він не створює нового рисунка ліктя чи кисті. Програмне потрапляння точки хвату не доводить художньо правильний хват.

Для приймання потрібен локальний художній прохід: окремі стиснуті/опорні кисті обох моделей та коригувальні поверхні сильних згинів ліктів, зі збереженням pivots і реєстрації. До цього основну гру не переводити на новий рушій. Критичні місця показані у крупних планах звіту.
