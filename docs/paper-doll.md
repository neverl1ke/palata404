# Paper Doll — головне меню

## Компоненти

`paper-doll-data.js` містить полотно 736×1417, слоти, фіксований порядок, базові PNG та каталог візуальних предметів. `paper-doll.js` відповідає за перевірку стану, вибір комплекту, збереження, рендеринг та селектори гардероба. `script.js` зберігає сумісні `setGender`, `setFace`, `updateCharacterLayers` й використовує новий компонент.

`#character-container` залишено на попередньому місці у палаті. Усередині `#character-paperdoll` містить 13 абсолютних PNG-шарів. Усі використовують спільне полотно й масштаб; порожні шари приховані та не мають `src`. Розміри контейнера залежать від сцени, а не від завантаження PNG.

Порядок: `baseBody`, `pants`, `footwear`, `upperBody`, `outerwear`, `armor`, `loadout`, `gloves`, `back`, `headwear`, `face`, `weapon`, `accessory`. `z-index` задається індексом порядку. Новий слот додається у конфігурацію та порядок; відсутній `img` створюється рендерером автоматично. Ідентифікатори й назви слотів є довіреною конфігурацією проєкту.

## Стан і сумісність

Один JSON `palata404_paper_doll` з `schemaVersion: 1` зберігає `selectedGender` (`male` / `female`), `activeViewMode` (`patient` / `combat`), `patientLoadout` та `combatLoadout`. У кожному комплекті — незалежний набір `slot: itemId | null`. Базове тіло обирається статтю, не екіпірується вручну. Стать спільна для двох комплектів; предмети при її перемиканні зберігаються.

За відсутнього або пошкодженого JSON перенесено старі допустимі стать та обличчя у «Пацієнта»; «Спогад» починається порожнім. Новий валідний JSON має пріоритет над legacy-ключами. Невідомі предмети, невідповідні слоти й некоректні режими відкидаються. Старі ключі статі й обличчя підтримуються; невідомі legacy-шляхи волосся та одягу не завантажуються, самі старі записи не видаляються.

Збереження проходить через існуючі `safeStorage*` та `saveGameProgress`, без нових нагород або бойових формул. Невдалий запис залишає вибір у пам’яті та показує повторне збереження у гардеробі. JSON атомарний для обох комплектів. Це локальні налаштування зовнішності браузера, як старий гардероб: немає синхронізації між пристроями чи окремої серверної прив’язки до акаунта.

Візуальні зразки не надають предметів інвентаря, не змінюють `equippedGear`, броню, шкоду, ресурси або прогрес. «Спогад» — другий комплект для перегляду, без автоматичного перемикання за божевіллям чи стартом бою.

## PNG та додавання предметів

Використано незмінені `base_male.png`, `base_female.png`, `face_1.png` — `face_6.png`. Бази вже мають спільне прозоре полотно 736×1417. Обличчя — менші вирізки; їхні альфа-межі виміряні й перетворені на `placement` у координатах спільного полотна. Вони масштабуються пропорційно, з видимою головою заввишки 177 px і верхньою точкою 25 px у вихідному полотні. Старе розтягування обличчя на 29% усього персонажа усунуто.

Для верхнього одягу, штанів, взуття, шолома, бронежилета й зброї готових PNG немає. Каталог містить по одному названому зразку з `image: null`: їх можна незалежно вибрати та зняти, стан зберігається, шар порожній, гардероб пояснює недоступність зображення. Нові PNG не генеровано, бойові спрайти та іконки не використано як одяг.

Приклад майбутнього предмета:

```js
{ id: 'coat-01', slot: 'outerwear', name: 'Пальто',
  genderVariants: { male: 'assets/paper-doll/coat-01-male.png', female: 'assets/paper-doll/coat-01-female.png' } }
```

Нові шари готуються як прозорі PNG 736×1417 з тією самою позою, масштабом і координатами тіла. По краях зберігається прозорий простір; не обтинати PNG до предмета. Для старих вирізок можна задати `placement: { x, y, width, height }` у координатах полотна. Без `placement` шар займає повне полотно.

Пошук ресурсу: варіант обраної статі → спільний `image` → доступний варіант іншої статі. Допускаються тільки локальні PNG-шляхи; довільні зовнішні URL або переходи `..` не завантажуються. При помилці завантаження перевіряється наступний кандидат, а якщо їх немає — шар приховується без іконки зламаного зображення. Невдалий ресурс не запитується повторно в цій сесії; вибір предмета залишається збереженим. Виправлений ресурс знову перевіряється після перезавантаження.

Для повного гардероба потрібні узгоджені PNG-шари для обох тіл, їхні стабільні ID та предметні назви в каталозі. Видача/придбання косметики й зв’язок із бойовим інвентарем залишаються наступними окремими етапами.

## Перевірки

Node перевіряє міграцію, нормалізацію, незалежність комплектів, відсутність впливу на бойові дані, відновлення після перезавантаження, помилки PNG, порядок шарів, помилки запису й повторне збереження. Playwright перевіряє UI гардероба, стать, вибір/зняття, збереження, масштаб обох тіл та облич на шести розмірах екрана, накладання повнорозмірних шарів і приховування/підміну відсутніх PNG. Зображення для перевірки повних шарів додаються тільки як тимчасові браузерні фікстури.
