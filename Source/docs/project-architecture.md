# Компоненти та безпечна розробка

Гра — статичний браузерний клієнт без збірки. `index.html` є точкою входу GitHub Pages; стилі — `style.css`. Класичні скрипти використовують спільні глобальні bindings, тому їхній порядок у HTML є контрактом, а не довільним списком.

| Компонент | Відповідальність | Основні залежності |
|---|---|---|
| `icons.js` | Локальні SVG та міграція старих emoji | `assets/icons/` |
| `staff-archive-data.js` | Конфігурація документів та колекцій | каталог босів під час виконання |
| `battle-results.js` | Післябойовий протокол, журнал нагород, презентація | safe storage, рейдовий і кадровий архіви |
| `raid-archive.js` | Персональні історичні знімки, ліміт, tombstone та owner ID | battle result normalization, storage |
| `staff-archive.js` | Документи, колекції, pity, ідемпотентні нагороди | боси, збереження, результати боїв |
| `paper-doll-data.js` | Каталог, шари, PNG, placement, гендерні обмеження | затверджені assets |
| `hair-color.js` | Палітра, перефарбування RGB, обмежені promise-кеші | Canvas, джерельні PNG |
| `paper-doll.js` | Міграція косметики, комплекти, front/rear, маски | дані, інвентар, палітра |
| `wardrobe.js` | Каталог, огляд, вибір, палітра та картки | Paper Doll та DOM |
| `script.js` | Ініціалізація, прогресія, інвентар, медицина, карта, бойовий цикл, модальні вікна | усі модулі вище |

Порядок ініціалізації: ідентичність → архів рейдів → pending battle journal → кадровий журнал → нормалізація stats/inventory/equipment → Paper Doll → спортзал/енергія → боси → відновлення історії → DOMContentLoaded. Функції пізніших скриптів доступні через hoisting лише після завантаження самого файла; ранній top-level виклик не повинен торкатися неініціалізованого `let/const`.

## Збереження

Існуючі ключі `palata404_*` збережені. Основні stats/inventory/equipped/progress/gym — локальні JSON; косметика — schema v2 з міграцією legacy/v1; вигляд спільний, `patientLoadout` та `combatLoadout` окремі. Архіви прив'язані до browser/Telegram owner ID. Два reward-журнали дозволяють відновити перерваний запис без повторного EXP/валюти; їх не можна заміняти простим `localStorage.clear()` або неатомарним загальним reset.

Веб-ID та Telegram initData тут визначають локальний профіль, **не є серверною авторизацією**. Місцеві помічники в бою — симуляція клієнта; backend/multiplayer synchronization у цьому репозиторії немає. Конкурентні вкладки можуть перезаписувати основний stats-save; per-raid записи захищені краще. Повноцінна міжвкладкова/серверна транзакційність — окрема задача, не прихований рефакторинг балансу.

## Ресурси й інструменти

- Корінь зберігає чинні URL запуску й старі legacy PNG; масове перенесення runtime-файлів зламає кеші, документацію та старі посилання.
- `assets/` — ігрові SVG, голови/маски, зачіски, одяг і затверджені джерела. Не оптимізувати художні PNG шляхом зменшення якості.
- `art/` — точні примірки тунік, потрібні тестам.
- `tests/fixtures/` — договори SHA, альфи, реєстрації та старих сейвів; це не непотрібні дублікати.
- `tools/` — відтворювані перевірки й одноразові історичні кроки обробки. Старі repair/prepare/refresh скрипти треба запускати **лише з відповідним вихідним snapshot**, не послідовно поверх фінальних assets. Їх збережено для provenance.
- `review/` — історичні публічні звіти, PNG/JPG, галереї й маніфести. Відсутність runtime-запиту не дозволяє їх видаляти: перевіряти також посилання з документації.
- `.github/workflows/checks.yml` — syntax, Node, Python/Chromium. Pages публікує `main`; feature-гілки не є deployment-залежностями.

## Перевірки перед публікацією

```sh
node --test --test-isolation=none tests/game-logic.test.cjs
python -m unittest discover -s tests -v
python tools/audit-project.py --output test-results/project-inventory.json
python tools/check-project-browser.py --output test-results/project-browser
python tools/benchmark-paper-doll.py --output test-results/paper-doll-benchmark.json
```

Швидкість із синтетичного benchmark — час 100 синхронних повторних рендерів, не FPS, не час завантаження через мобільну мережу. Порівнювати за однакового браузера, PNG та навантаження. Після push перевіряти саме опублікований HTTPS index і версії runtime-файлів.
