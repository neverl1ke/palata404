## Виміряна оптимізація

Незмінні crown-контури кешуються через WeakMap за вихідним масивом і варіантом: default / approved shoulder transform / alternative messy seam. Новий масив контурів має новий запис; cache не залежить від HP, енергії або кольору. Збережено початкові формули й точний polygon. Стилі, джерела та порядок шарів **усіх 90 комбінацій ідентичні**: [до](geometry-before.json), [після](geometry-after.json).

Парний benchmark використовує один Chromium, ті самі PNG/HTML/viewport, snapshot початкового renderer та поточний renderer: [performance.json](performance.json).

## Тести та браузерна перевірка

Після змін: **80/80 JavaScript та 97/97 Python/Chromium**. Нових перевірок — 5 Node та 6 Python/Chromium; старі 166 перевірок збережено. Нові Python-контракти контролюють незмінну графіку, доказ видалення, 37 точних шляхів/регістр, початкові посилання, стабільний front/rear після повторних рендерів/reload та відхилення неправильного ID боса.

Журнали: `logs/after-node.log`, `logs/full-after/shard-*.log`; машинний підсумок — [summary.json](logs/full-after/summary.json). Ізольовані shards мають власні браузерні профілі/HTTP-сервери; жоден тест не виключено чи повторно запущено для приховування збою. Шість нових тестів додатково пройшли цільовий прогін.

Незалежний обхід реального `index.html`: **90 комбінацій × 3 кольори (original/black/white) × 4 фони = 1080 перевірок**; 11 екранів; усі категорії/слоти; 320/360/390/430/768/1440 px; збереження/reload; контроль одноразового нарахування. JS/HTTP-помилок немає. Клік по арені, заборона другого удару в cooldown і контрудар також окремо пройшли; опублікований обхід повторює цей сценарій. Керована фіналізація zero-HP використовується лише для детермінованої перевірки payout, а не видається за ручне проходження повного бою.

Галерея містить 18 пар реальних screenshot: гардероб/інвентар/досьє/архів на 320/390/768/1440 та чоловічий/жіночий Paper Doll зі світлим волоссям. Незмінну графіку не підмінено генерацією. UI не редизайнився: існуючі responsive/keyboard/focus/scroll контракти підтверджено.

До CI додано compileall інструментів/тестів та `tools/audit-project.py --check`; інвентаризатор не видаляє файли автоматично. `tests/__init__.py` робить suite явно імпортованим для відтворюваного шардованого запуску.

## Межі й відкриті рішення

- Фізичні Android/iPhone та Telegram WebView недоступні; viewport Chromium не замінює їх.
- Серверної синхронізації немає. Reward-журнали й per-raid записи перевірені, але одночасні вкладки можуть конфліктувати при записі основного stats-save. Нова міжвкладкова/серверна транзакційність потребує окремого проєктування та міграційних тестів.
- Частота видачі нагород Збирачем — дизайнерське рішення; обмеження не додавалося. Дев’ятий поверх, загальні завдання, пошта, звук і донат залишені запланованими заглушками.
- Активний бій після reload не відновлюється, як і раніше; вже отримані нагороди/колекції збережені.
- Максимальні gameplay-ліміти рівня/валют та операції поблизу Number.MAX_SAFE_INTEGER потребують окремої політики. Вільно обрані числові caps не впроваджувалися як «очищення».
- Художні питання попередніх портретів цим технічним етапом не переглядалися. Слабке мережеве з’єднання, фізична пам’ять телефона та поведінка сторонніх сервісів не оцінюються синтетичним render benchmark.
- Глобальна класична архітектура та великий script.js залишаються технічним боргом; безпричинний ES-module rewrite створив би ризик порядку ініціалізації. Наступні винесення варто робити за окремими контрактами збереження.
